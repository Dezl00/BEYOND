# Beyond فواتير
مساحة ويب عربية بـNext.js وNeon وGemini، تعرض صفًا واحدًا لكل فاتورة بوصف عام.

## النشر
1. استورد مستودع BEYOND في Vercel: Framework هو Next.js وRoot Directory هو ./.
2. استورد BEYOND.vercel.env في Environment Variables لبيئة Production ثم Deploy.
3. كلمة الدخول هي APP_PASSWORD. تغييرها وإعادة النشر يبطل جلسات الدخول السابقة.
4. أضف أكواد التصنيفات الفعلية وارفع دفعة صغيرة للمراجعة.

ملف ENV الكامل منفصل عن المستودع. .env.example يحتوي أسماء المتغيرات فقط.
ENABLE_EXPERIMENTAL_COREPACK=1 يفعّل إصدار pnpm المحدد، وإعدادات vercel.json تضبط البناء والمنطقة fra1.

## البيانات
- كل فاتورة صف واحد: رقم، تاريخ، مورد، رقم ضريبي، وصف عام، تصنيف، كود، قبل الضريبة، الضريبة، والإجمالي النهائي.
- الوصف المقترح يعتمد على التصنيف العام، مثل «مشتريات مواد كهرباء»، ويمكن تعديله يدويًا.
- لا تُستخرج أسماء المنتجات الفردية أو الكميات إلى الجدول والتصدير.
- لا توجد حقول أو أعمدة أو فلاتر أو تفضيلات للأشخاص المسؤولين عن المصروف.
- المساحة الجديدة فارغة؛ لا توجد سجلات أو تصنيفات أو رسوم تجريبية.
- كل صفحة PDF فاتورة مستقلة. الرفع المتعدد حتى 50 صفحة/صورة في الدفعة و25 MB للملف الأصلي.
- التصوير بالكاميرا، حفظ المسودات، واستكمال المعالجة المحلية مدعومة.
- البحث والتصفية حسب الرقم والمورد والوصف العام والتصنيف والتاريخ.

## المعاينة
المعاينة بملء الشاشة، مع ثلاث طرق للعرض: الجدول والأصل، الجدول بالكامل، أو الأصل بالكامل.
زر «تعديل جماعي» يفتح جميع الحقول، ويمكن تطبيق التصنيف على عدة فواتير.
تُعرض المبالغ الثلاث المقروءة من الأصل بشكل مستقل أسفل الجدول، مع إعادة الحساب منها.
لو المبلغ المقروء كنهائي يبدو قبل الضريبة، تظهر ملاحظة وزر لتأكيد نوعه بعد مراجعة الأصل.
الاعتماد يتطلب اكتمال الحقول والتصنيف ومطابقة المبالغ. المسودات يمكن حفظها للمراجعة.
الاشتباه بالتكرار يعرض السجل السابق، مع الاستبعاد أو سبب مكتوب لإعادة التسجيل.

## المبالغ والضريبة
- لا تعتبر كلمة «الإجمالي» وحدها دليلًا على أن المبلغ شامل الضريبة.
- الاستخراج يقرأ subtotalBeforeTax وvatAmount وtotalIncludingTax كلًا على حدة؛ القيم غير المكتوبة تبقى null.
- لو المتاح قبل الضريبة 1,000 وضريبة 150، يُحسب النهائي 1,150.
- لو المتاح مبلغ نهائي شامل 1,150 فقط، تُستخرج الضريبة بالمعادلة 1,150 × 15 ÷ 115 = 150، والصافي 1,000.
- تعديل حقل «قبل الضريبة» يضيف الضريبة؛ تعديل «النهائي» يفصل الضريبة من المبلغ الشامل.
- القيم المكتوبة المتطابقة حسابيًا تُحفظ كما هي، ويظهر تنبيه إذا اختلفت عن حساب 15% بسبب التقريب أو النسبة.
- التناقض بين المبالغ أو التباس قبل/بعد الضريبة يمنع الاعتماد حتى التصحيح أو تأكيد نوع المبلغ.
- الحسابات بالهللات الصحيحة، ولا تتكرر قيمة الفاتورة بسبب تعدد المنتجات.

## ترحيل البيانات القديمة
الصيغة الجديدة schemaVersion=2.
عند فتح البيانات القديمة، تُحوّل تلقائيًا إلى سجل واحد لكل فاتورة، ويُنشأ وصف عام من التصنيف.
تُحذف حقول الأشخاص والكميات ومصفوفة المنتجات القديمة من السجل والتفضيلات وقائمة أعمدة التصدير.
الفواتير التي كانت موزعة على تصنيفات متعددة تنتظر اختيار تصنيف عام واحد.
الترحيل المحلي يحفظ الصيغة الجديدة، وقراءة Neon ترحّل السجل ذريًا مع التحقق من revision حتى لا تستبدل تعديلًا متزامنًا.
رقم الفاتورة والتاريخ والمورد والأصول وإجمالي الفاتورة محفوظة، وأي مبلغ مشتبه في قراءته يُعرض للمراجعة.

## الحماية والحفظ
- نسخة فردية بكلمة مرور وجلسة AES-GCM وHttpOnly وSameSite=Strict لمدة 7 أيام.
- جميع خدمات البيانات تتحقق من جلسة الدخول، والطلبات المعدلة تتحقق من المصدر.
- المفاتيح تبقى على الخادم؛ البدائل المدخلة في الإعدادات تحفظ في Cookie مشفرة.
- البيانات محفوظة محليًا وتزامن مع Neon عبر beyond_workspaces. رقم المراجعة يمنع الاستبدال الصامت.
- الأصول متاحة 24 ساعة على جهاز الرفع فقط. تُحجب بعد الانتهاء ويُنفذ التنظيف أثناء تشغيل الموقع أو عند فتحه.
- الصفحات ترسل إلى Gemini للاستخراج؛ الملفات الكبيرة تُهيأ محليًا لتناسب حد إرسال Vercel.
- إدارة الفرق وفصل جداول البيانات للتوسع مراحل لاحقة.

## المتغيرات
GEMINI_API_KEYS وGEMINI_MODEL وDATABASE_URL وAPP_PASSWORD وAPP_ENCRYPTION_KEY.
الافتراضي Gemini 2.5 Flash، ويمكن اختيار نموذج آخر من الإعدادات.
ضع كل المفاتيح في متغير واحد: GEMINI_API_KEYS=key1,key2,key3,key4
عند 429 يجرب المفتاح التالي تلقائيًا لنفس الفاتورة، مرة واحدة لكل مفتاح، ويستمر بالمفتاح الذي نجح. يحترم Retry-After وRetryInfo ويؤجل المفاتيح المستنفدة داخل نسخة الخادم النشطة.
عند نفاد الجميع تظهر رسالة واضحة مع Retry-After، وتظل الفاتورة متاحة لإعادة المحاولة. لا يبدل المفاتيح لأخطاء الملف أو النموذج أو الصلاحيات.
حدود Gemini تخص مشروع Google، فالمفاتيح التابعة لنفس المشروع تشترك في الحصة: https://ai.google.dev/gemini-api/docs/rate-limits
تظل المتغيرات القديمة مدعومة للترقية، لكن GEMINI_API_KEYS له الأولوية على مفتاح قديم محفوظ. يمكن إدخال قائمة بديلة صراحة من الإعدادات.
ENABLE_EXPERIMENTAL_COREPACK=1 لاستخدام إصدار pnpm المحدد.

## التشغيل
Node.js 22.13+ وpnpm 11.25:
- pnpm install
- أضف المتغيرات إلى .env.local
- pnpm dev
- pnpm check
- pnpm test
- pnpm build
- pnpm start

## التحقق
اختبارات التبديل التلقائي ونفاد جميع المفاتيح والمهلة واحترام وقت الانتظار، واختبارات الحسابات، تفسير المبالغ، الترحيل، التكرار، حذف الحقول القديمة، وصف واحد وتصدير صف واحد.
اختبار فعلي لأربع فواتير PDF تجريبية عبر Gemini: المبالغ الثلاث، قبل الضريبة فقط، النهائي فقط، وإجمالي ظاهر قبل الضريبة.
اختبار Excel يشمل صفًا واحدًا ومبالغ قبل الضريبة والضريبة والنهائي بدون أعمدة قديمة.
فحص الواجهة داخل متصفح لم يكتمل؛ تحقق HTTP من الصفحة والمعاينة يعتمد على فحص المكونات والبناء.
PDF يحافظ على العربية كصور عالية الدقة؛ النص فيه ليس قابلًا للبحث.
